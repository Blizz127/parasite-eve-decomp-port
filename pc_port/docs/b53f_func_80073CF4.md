## ABI and installed target

The execution-relevant ABI is:

```c
pe_addr_t func_80073CF4(uint32_t dma_channel, pe_addr_t handler);
```

Both arguments and the return are 32-bit retail values. `handler` is a guest
function identity, never a native function pointer.

The retail wrapper loads `D_8009566C = 0x8009564C`, then the field at
`0x8009564C + 4`. That field is initially zero in the executable. The first
guard-passing ResetCallback path installs the backend as follows:

1. `func_800744D4` returns guest identity `0x800746A0`;
2. `func_80073E28` calls `func_8007436C` at `0x80073EDC`;
3. its `0x80073EE0` delay slot stores the returned identity at jump-table
   field `+4`.

The native ResetCallback already collapses the SDK jump-table plumbing, as
does the older translated `func_80073D24` wrapper. B53F therefore binds the
proven post-ResetCallback field to numeric guest identity `0x800746A0` at
the instant of dispatch. It does not materialize a host function pointer or
claim pre-ResetCallback/dirty jump-table behavior.

return zero. Those effects are evidence for the next rung, not B53F effects.
