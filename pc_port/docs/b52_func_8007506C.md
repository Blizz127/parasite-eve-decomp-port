# Phase 6E-B52 — LoadImage wrapper to the GPU boundary

## Recovery and scope

B52 resumed from the intentional dirty tree on accepted B51 commit
`9c494f0ac09313681a6a99ebc3a6a04ed88eb7fc`. The pre-existing inventory was
exactly one modified file, `game/boot/func_8006E1C0_port.c`, and one untracked
file, `game/boot/func_8007506C_port.c`. No process had a cwd in this checkout,
no Git lock existed, and ancestry was proven through B50 corrective commit
`37990cf5fe5859285e2718415231eb9961cf353b` to B49 commit
`33042dba2975079175da0eb01c46d650e2e842a6`.

Kimi had already selected the correct architecture, drafted the wrapper and
validator source, and rewired both B51 calls to a transient `RECT`. The audit
retained that direction but corrected the retail RECT width, validator's
stack-passed fifth diagnostic argument and indirect print targets, removal of
a non-retail jump-table equality abort, exact GPU-boundary register logging,
and forwarding of the dispatcher's return value.

## Retail contracts

`func_8007506C` occupies `0x8007506C..0x800750CC` (exclusive), 0x60 bytes / 24
words, at executable file offset `0x6586C`, live in
`asm/disc1/654C8.s:283-310`. Its ABI is:

```c
int func_8007506C(const RECT *rect, pe_addr_t data);
```

`RECT` is exactly four signed 16-bit fields: x, y, w, h. The function calls
`func_80074E28(0x800118D4, rect)`, reloads `D_80095744`, loads `jtb[8]` before
`jtb[2]`, sets `a2 = 8`, and executes the indirect call with `a3 = data` in
the delay slot. It forwards the indirect return unchanged. The string at
`0x800118D4` is `LoadImage`.

`func_80074E28` occupies `0x80074E28..0x80074F44` (exclusive), 0x11C bytes /
71 words, at file offset `0x65628`, live in
`asm/disc1/654C8.s:118-197`. All persistent accesses are reads; every store is
stack-relative. Debug level zero is silent. Level one applies the retail
signed width, height, coordinate, positivity, and limit checks and prints
only an invalid RECT. Level two always prints. Both diagnostic calls reload
the function pointer at `D_80095748`; the RECT print passes height as the
fifth, stack-passed argument. The validator has eight direct callers and is
required because the wrapper always calls it, so retaining the complete small
body does not create an unsupported second rung.

## Dispatch contract and boundary

`D_80095744` is initialized to the 16-entry table at `0x80095704`. The exact
entries are:

| Index | Value | Index | Value |
|---:|---:|---:|---:|
| 0 | `0x800117AC` | 8 | `0x80076664` |
| 1 | `0x80076C10` | 9 | `0x80076EE4` |
| 2 | `0x80076C34` | 10 | `0x80076B44` |
| 3 | `0x80076434` | 11 | `0x80076354` |
| 4 | `0x80076B20` | 12 | `0x80076BE0` |
| 5 | `0x80076B58` | 13 | `0x80077144` |
| 6 | `0x80076B98` | 14 | `0x8007633C` |
| 7 | `0x800768A0` | 15 | `0x80077294` |

The exact unresolved call is therefore:

```text
target = 0x80076C34
a0 = 0x80076664
a1 = pointer to the transient 8-byte RECT
a2 = 8
a3 = the 32-bit source address
return = func_80076C34 return, forwarded unchanged
```

The boundary is necessary. `func_80076C34` manages a 64-entry, 96-byte GPU
command ring and producer/consumer state; polls GPUSTAT at `0x1F801814` bit
`0x04000000`; observes DMA2 CHCR at `0x1F8010A8` bit `0x01000000`; reaches
the queue pump `func_80076EE4` and wait loop `func_80077404`; and can return
-1. Worker `func_80076664` writes GP0/GP1 and DMA2 MADR/BCR/CHCR. B52 does
not implement or fake these queue, hardware-timing, readiness, drain, or
completion semantics.

Both `func_8006E1C0` calls were reverified. The first substitutes height
0x100 only when the image height byte is zero and uses
`base + (image_offset & 0xFFFFFF)`. The optional CLUT call uses its raw height
byte and the wrapping address
`base + image_offset + (clut_offset & 0xFFFFFF)`. The host RECT is synchronous
and transient; no host pointer enters guest RAM.
