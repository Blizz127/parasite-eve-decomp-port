## Verdict

`func_8005B91C` is classification 1, translated retail logic. It is a
deterministic signed table-index and interpolation decomposer. It selects one
of the 0x200-byte tables returned by translated `func_8005DB8C`, performs the
retail binary search, writes the selected signed index through nullable `a2`,
and optionally writes a signed 0..48 interpolation fraction through nullable
`a3`. It has no unresolved dependency and no platform, SDK, callback,
hardware, polling, blocking, host-time, or environment behavior.

non-null record holder it stops at `func_80052F24` after executing that call's
retail delay-slot write. The actual Disc 1 boot state takes B43's earlier
null-holder return, so the fresh real-disc strict frontier becomes

## True ABI and output contract

The semantic retail signature is:

```c
void func_8005B91C(int32_t table_number, int32_t key,
                   pe_addr_t index_out, pe_addr_t fraction_out);
```

`a0` is a signed 32-bit table number whose wrapped low 32 bits feed
`func_8005DB8C`; all executable callers use nonnegative table selectors.
`a1` is a signed 32-bit key. `a2` and `a3` are independently nullable
32-bit output pointers. Neither is read. On every normal path the calculated
index is stored as one word through non-null `a2`. If `a3` is non-null, one
word is stored after the `a2` store: the interpolation fraction when index is
below 98, otherwise exactly 48. Thus aliased outputs are legal and the later
fraction store wins. There is no failure path that leaves a non-null output
untouched.

The body has one epilogue and no contractual return. All 18 callers ignore
`v0`. Its residual value is `(index < 98)` when `a3==0`, and 48 when `a3` is
non-null. The port deliberately exposes `void`, rather than preserving an
unconsumed register accident.

Retail stack output pointers cannot be represented by `pe_addr_t` in native
C. `PE_func_8005B91C_HostOut` is a separate full-width adapter for translated
callers with host stack temporaries. Both public forms use the same arithmetic
core and identical index-before-fraction ordering. No host pointer is
truncated, placed in guest RAM, or confused with a guest address.

## Exact algorithm and arithmetic

Let `base = func_8005DB8C(table_number)`. Search begins with index 64 and
step 32. Each iteration first reads signed `table[index]`:

1. If `key >= table[index]`, add `step` to the index.
2. Otherwise read signed `table[index-1]`. If `key < table[index-1]`,
   subtract `step`; otherwise set `step` to zero.
3. Arithmetic-shift `step` right once and repeat while nonzero.

After the loop retail subtracts one from the index and applies only the
signed upper clamp `index >= 99 -> 98`. There is no lower clamp. Given the
fixed search start/steps, the minimum normal selected index is zero. Search
reads can range from `base` through `base+0x200` inclusive; all are four-byte
reads.

For index below 98 retail reads `high=table[index+1]` before
`low=table[index]`. Equal words yield fraction zero. Otherwise:

```text
delta       = wrap32(key - low)
numerator   = wrap32(delta * 49)       # exact shift/add sequence
denominator = wrap32(high - low)
fraction    = signed numerator / signed denominator, truncating toward zero
fraction >= 49 (signed) -> 48
```

Negative fractions are not clamped. Index 98 produces fraction 48 without
adjacent-table reads. The equality branch makes divide-by-zero unreachable.
Retail nevertheless contains `break 7` for zero and `break 6` for
`INT32_MIN/-1`; production explicitly aborts the latter instead of invoking
C signed-division undefined behavior.

translated `5DB8C`. Data-dependent four-byte reads span selected
