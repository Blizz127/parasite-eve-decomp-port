## ABI

```c
pe_addr_t func_800746A0(uint32_t dma_channel, pe_addr_t handler);
```

Both arguments and the return are 32-bit retail values. `handler` and the
returned previous handler are guest function identities, never native
function pointers and never booleans. There is no third argument: `a2` is
overwritten by the first instruction and `a3` by the fifth.

## Channel range and index contract

Retail performs **no** channel validation of any kind — no minimum, no
maximum, no signedness test, no masking, no rejection. The measured
consequences, reproduced exactly and covered by tests and the oracle:

| Channel | Slot address | Enable bit | Behaviour |
| --- | --- | --- | --- |
| 0..6 | `0x800956C0 + 4*ch` | `1 << (ch+16)` | in-table, dispatchable |
| 7 | `0x800956DC` | `1 << 23` = master | in-table, never dispatched |
| 8 | `0x800956E0` | `1 << 24` (a W1C flag) | one word past the table |
| `0xFFFFFFFF` | `0x800956BC` (DICR pointer) | `1 << 15` | wraps below the table |

`sllv` uses only the low five bits of `channel + 16`, so the shift amount
is `(channel + 16) & 31`. Address arithmetic is exact 32-bit wrapping
`sll`/`addu`.

The native translation reproduces this arithmetic verbatim and reads/writes
through the existing guest-RAM authority. A channel whose computed slot
falls outside the modeled 2 MiB RAM is an access this port cannot
represent; the guest-memory authority reports it rather than corrupting
host state. No executable caller produces one.

## Previous-handler semantics

Every return path is `addu v0,a3,zero` — the full 32-bit word read from the
slot before any decision. No normalisation and no truncation.

| Case | Slot store | DICR access | Return |
| --- | --- | --- | --- |
| empty → install | `slot = handler` | read + write | `0` |
| existing → replace | `slot = handler` | read + write | previous |
| existing → remove (`handler == 0`) | `slot = 0` | read + write | previous |
| zero → zero | none | none | `0` |
| same-handler reinstall | none | none | that handler |
| invalid channel | same as above at the raw address | read + write | word at that address |

The `beq a0,a3` at `0x800746BC` makes both no-op cases complete no-ops:
they perform no guest write and do not touch DICR at all.

## DICR read/modify/write

`D_800956BC` is a retail `.data` word holding the literal `0x1F8010F4`. The
setter loads that pointer and dereferences it; the register itself is the
B53B `pe_gpu` authority, reached through `PE_GPU_ReadDICR` /
`PE_GPU_WriteDICR`. No second DICR global, guest-RAM mirror, or duplicate
enable/pending state is created, and `PE_GPU_SetDMA2InterruptEnabled`
(channel-2-specific) is deliberately not used, because retail derives the
bit from the channel.

Install (`handler != 0`, `handler != previous`):

```text
DICR = (DICR & 0x00FFFFFF) | (1 << ((channel+16) & 31)) | 0x00800000
```

Removal (`handler == 0`, `previous != 0`):

```text
DICR = ((DICR & 0x00FFFFFF) | 0x00800000) & ~(1 << ((channel+16) & 31))
```

Both paths unconditionally set master-enable bit 23. On the removal path
the master OR happens **before** the channel-enable clear, so channel 7 —
whose enable bit *is* bit 23 — clears the master bit again. That asymmetry
is preserved rather than normalised.

The `0x00FFFFFF` mask means the written word carries zeros in bits 24..30,
so the W1C completion flags are never acknowledged by registration. A
pending channel-2 completion flag survives both an install and a removal;
this is verified against a genuine `PE_GPU_ServiceDMA2Completion` flag, not
a synthesised one. Unrelated lower control bits are preserved verbatim.

For the canonical call the measured result is exactly `0x00840000`
(master bit 23 + channel-2 enable bit 18) from an initial `0`.

## DICR bit 31 — verdict

**Verdict B: bit 31 is read and immediately discarded; it is never tested
and never written as one.**

The `lw` at `0x800746DC` / `0x80074718` reads the raw 32-bit word, and the
very next `and` with `0x00FFFFFF` clears bit 31 in the value written back.
No instruction in the body compares, branches on, or otherwise consumes it.
On PSX hardware bit 31 is the read-only derived master flag, so writing
zero there is inert.

The oracle proves the independence directly: the identical scenario run
against a DICR model that *does* synthesize bit 31 and one that does not
produces byte-identical returns, guest writes, and DICR writes.

Consequently **B53B is not extended**. Its deliberate omission of a
synthesized raw bit 31 remains correct and unobservable by this path. Bit
31 *is* consumed elsewhere — `func_80074520` compares `DICR & 0xFF000000`
against `0x80000000` and tests bit 15 for its error report — but that is
the DMA IRQ dispatcher, which B53G does not translate.

## I_MASK — verdict

**`func_800746A0` does not access I_MASK or I_STAT.** The body embeds no
`0x1F801074` or `0x1F801070` literal and performs no MMIO access other than
the two DICR operations; the oracle asserts both. The retail DMA
interrupt-source installation belongs to `func_800744D4`'s
`func_80073CC4(3, func_80074520)` call, which remains the pre-existing
deferred item recorded by B53F.

The single 16-bit `pe_irq` authority from B53D is therefore untouched by
registration, and tests assert the mask is unchanged across it. The only
I_MASK activity on the canonical path is `func_80076C34`'s own exchange and
its retail restore, which happens strictly after producer publication and
is not suppressed by any host frame-limit or run-control state.

## Operation ordering

Recovered from the literal words, not assumed:

1. compute the raw slot address (no validation);
2. read the previous handler;
3. compare against the new handler and return immediately if equal;
4. branch on `handler == 0`;
5. **store the slot** (`0x800746D8` / `0x80074714`);
6. **then** read DICR (`0x800746DC` / `0x80074718`);
7. compute and write DICR;
8. return the previous handler.

The slot store strictly precedes the DICR read on both paths; the oracle
checks this from the execution trace. No interrupt delivery occurs inside
the function, so registration is atomic from the native port's perspective
without inventing concurrency.

## Queue publication

Canonical execution reaches ring publication, so `func_80076C34`'s literal
enqueue block `0x80076D68..0x80076EA0` is translated. It has no unresolved
dependency: its only call is the already-translated `func_80073E10`.

Ring geometry, proven from the executable words: 64 entries of 96 bytes at
`D_800BD030`, with `+0x00` worker identity, `+0x04` argument, `+0x08`
auxiliary, and the copied inline payload from `+0x0C`. Entry offset is
`producer * 96` (`sll`/`addu`/`sll` at `0x80076DB0..0x80076DB8`).

The published second LoadImage request is exactly:

| Field | Value |
| --- | --- |
| worker (`+0x00`) | `0x80076664` |
| argument (`+0x04`) | `0x800BD03C` — guest address of the copied payload |
| auxiliary (`+0x08`) | `0x8012B8B8` — source guest address |

The payload is copied before publication, the entry is complete before the
producer advances, and the producer advances in the `0x80076EA0` delay slot

no host queue exists.

The `0x80076D80` word count is signed (`bgez`/`addiu 3`/`sra 2` then a
signed `slt`), so a negative byte count copies nothing and only the
metadata words are written; that path is covered by tests.

Retail performs no bounds check on the copy source or the entry. A span
this port cannot represent — an out-of-RAM copy source, or a copy wider
than the 84-byte payload area — becomes a visible honest boundary
(`func_80076C34_enqueue_span`) after the registration retail had already
performed, and before any publication. This mirrors B53E's source-span
preflight rather than aborting the host or silently narrowing the copy.

## Oracle and tests

`tools/b53g_oracle.py` is independent of production C. It verifies the
executable SHA-1, the file offset, the exact range, the body SHA-256, all
43 literal words, both branch targets, the jump target, all four delay
slots, and the absence of any call. It then executes those words on a
MIPS-I interpreter with exact delay slots, against guest RAM plus a DICR
model with PSX W1C flag semantics and an optional read-only master flag.
It covers the callback-table indexing, all eight in-range channels, the
above-range and negative channels, first install, replacement, removal,
zero-to-zero, same-handler reinstall, full-width previous-handler returns,
both DICR RMW expressions, unrelated control-bit and completion-flag
preservation, the channel-7 master asymmetry, the explicit bit-31
independence proof, the absence of any non-DICR MMIO access, the
whole-executable caller census, the initialization owner, and the canonical
`func_80073CF4` call context. Mutation probes confirm it fails on a
corrupted literal word, a wrong master bit, a changed wrapper field, and a
broken W1C model.

Seven focused production tests cover the exact ABI and executable caller
channels, the channel-range contract including below/above range, the full
handler lifecycle, the exact DICR install/removal RMW with a genuine
pending completion flag, registration-is-not-delivery (full-RAM canary,
VRAM samples, GPU/DMA/VBlank/I_MASK inertia), reset lifecycle and repeated
determinism, and the new strict frontier. Four B53F tests and three
B53C/B53D tests were retargeted from the removed boundary to the measured
registration and publication facts.
