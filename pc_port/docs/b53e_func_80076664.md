# Phase 6E-B53E — `func_80076664` LoadImage issue worker

## Result

B53E translates the execution-proven direct-path Psy-Q LoadImage issue
worker against the single B53B GPU/DMA2 authority. The implementation keeps
the retail guest identity and address ABI, clamps and writes back the guest
RECT fields in retail order, performs the exact GPUSTAT wait, emits the
retail GP1/GP0 sequence, feeds the 0..15 CPU words, and issues the DMA2
suffix asynchronously. It does not complete DMA, dispatch a callback, pump
the retail ring, or create a second GPU/queue authority.

The exact non-timeout software prefix of `func_80077404` is included so a
clear GPUSTAT bit can repeat without invented progress. Its recovery suffix
remains an honest boundary. Canonical Disc 1 enters GPU-ready, bypasses that
dependency, issues its first transfer, and returns from the worker with DMA2
still busy. The next LoadImage request therefore selects the existing retail
enqueue branch and fresh strict execution stops at:

```text
FATAL: strict-stubs — first unresolved BOOTSTRAP_RET provider: func_80073CF4
       called from: func_80076C34
```

Bootstrap strict remains `func_8007F72C` from `func_800698D4`.

- `rect` and `source` are 32-bit guest addresses, never native pointers;
- `rect` is read synchronously and only its signed 16-bit `w` and `h`

## RECT and transfer arithmetic

`w` and `h` are loaded as signed halfwords. Each negative field becomes
zero; otherwise the signed configured limit is selected only when it is
less than the signed field. The selected 16-bit value is written back.
ResetGraph mode 0 establishes limits 1024 and 512, giving accepted clamps
`[0,1024]` and `[0,512]`. `x` and `y` are not clamped.

The literal register arithmetic is preserved:

```text
pixels  = low32((int32_t)w * (int32_t)h)
t       = low32(pixels + 1)
adjust  = low32(t + (t >> 31))
words   = arithmetic_shift_right(adjust, 1)
blocks  = arithmetic_shift_right(adjust, 5)
remain  = words - blocks*16
```

For the established nonnegative limits this is
`words=ceil(w*h/2)`, `blocks=words/16`, and `remain=words%16`. Production
uses explicit MIPS signed/shift helpers so host signed overflow and
implementation-defined casts are not used. `words<=0` returns `-1` after
the timeout initialization and clamp stores, before GPU MMIO.

## DPCR prerequisite audit and correction

Canonical B53D entered the worker with DPCR zero, while retail enables DMA2
before the first LoadImage. An executable-wide audit classified this as a
missing earlier translated retail store, not worker ownership and not a
B53B issue-gate defect.

The SHA-exact execution order is:

1. guard-passing ResetCallback `func_80073E28` writes exact DPCR
   `0x33333333` at `0x80073E7C`;
2. ResetGraph calls `func_80077144(mode=0)` at `0x80074AE4`;
3. mode 0 reads DPCR at `0x800771D4` and writes
   `old | 0x00000800` at `0x800771E0`;
4. canonical DPCR is therefore `0x33333B33` before the initialization byte
   is published and long before the first LoadImage.

The other concrete channel-2 enable is timeout recovery `func_80077404`
at `0x800774EC/0x800774F8`; it is recovery, not initialization. Other DPCR
writers operate on DMA3/4/6 or preserve a previously established channel-2
bit.

B53E restores the two missing operations at their existing native owners:

- guard-passing `func_80073C94` writes `0x33333333` through
  `PE_GPU_WriteDPCR`;
- collapsed `PE_Gpu_SetVideoMode`/`func_80077144` ORs `0x800` for retail
  modes 0/1/3/5 through `PE_GPU_EnableDMA2`.

Nothing enables DMA2 in `func_80076664`, `PE_Sdk_ResetState`, or a
speculative startup hook. Unrelated DPCR bits are preserved by the RMW.
The narrow correction does not yet claim the active-DMA CHCR abort behavior
of a repeated ResetGraph call.

## Source-safety envelope

Retail can fault on malformed guest input. A native port must not perform a
host out-of-bounds read or expose a partial CPU prefix before discovering an
invalid DMA suffix. After exact arithmetic and before GPUSTAT/MMIO, B53E
validates the complete original rounded span:

- nonzero 32-bit guest address;
- 4-byte alignment;
- `words*4` computed without narrowing overflow;
- complete span in the authoritative 2 MiB guest RAM;
- no low-address or KSEG mirroring and no clamping.

The zero/nonpositive retail path remains independent of source validity and
does not dereference the source. Exact end `0x801FFFC0` plus one 16-word
block is accepted; the first aligned crossing span is rejected.

B53E also adds the inert `PE_GPU_CanBeginImageLoad(needs_dma)` query. Before
the first GP1/GP0 write it requires an idle GP0 parser, no active DMA, and
the DPCR channel-2 bit only when blocks are required. Rejection mutates no
GPU state or VRAM. This prevents cache/header words from being interpreted
as pixels by a dirty parser and prevents a CPU prefix becoming visible
before a later DMA issue rejection. The query does not enable DMA, clear a
descriptor, advance readiness, or expose mutable platform state.

## GPUSTAT and timeout behavior

Retail tests only GPUSTAT bit 26 (`0x04000000`; set means ready for a GP0
word). Each read uses `PE_GPU_ReadStatus`; polling has no side effects and
never advances VBlank or completes DMA.

When clear, the worker calls `func_80077404`. B53E translates its bounded,
hardware-independent non-timeout prefix `0x80077404..0x80077454`:

1. inert VSync query;
2. signed comparison with `D_80095888`;
3. load old `D_8009588C`, publish `old+1` with 32-bit wrap;
4. signed comparison `0x000F0000 < old`;
5. return zero on the ordinary retry path.

On timeout it stops before recovery begins at `0x80077458`. It does not
invent GP1 reset, DMA abort, queue reset, DPCR recovery, diagnostics, or a
helper result. A native same-call clear-to-ready transition would require a
separately proven event mechanism, so the literal oracle supplies an
explicit `[clear, clear, ready]` status script while native tests prove a
held-clear recovery boundary and a distinct explicit ready transition.
