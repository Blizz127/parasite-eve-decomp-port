# Phase 6E-B53C — `func_80076C34` dispatcher prefix

## Result

B53C implements an honest retail prefix, not the complete GPU dispatcher.
It also translates the dispatcher’s one inseparable 13-instruction timeout
initializer, `func_800773D0`.

The production architecture choice is **E — OTHER PREFIX**:

- the canonical non-full path covers `func_80076C34` through the call and
  delay slot at `0x80076CA0..0x80076CA7`, then stops before consuming the
  unresolved `func_80073E10` I_MASK exchange result;
- the full-ring alternate stops earlier at `func_80077404`, call address
  `0x80076C68`;
- no ring entry is constructed or published in production;
- no worker, callback setter, queue pump, GPU readiness poll, or DMA event is
  simulated.

Fresh canonical Disc 1 strict execution in both normal and ASan/UBSan builds
now reports:

```text

       called from: func_80076C34
```

## True ABI and native adapter

The guest ABI is represented with 32-bit identities, never native function
pointers:

```c
int func_80076C34(pe_addr_t worker,
                  pe_addr_t argument,
                  int32_t copy_bytes,
                  uint32_t auxiliary);
```

`worker` is the guest identity of the retail command-issue routine. It is
not called, cast, or retained by this prefix. The known LoadImage identity is
`0x80076664`.

B52’s `func_8007506C` receives a transient native `RECT`. For the exact
`jtb[2] == 0x80076C34` target it now converts that RECT to two retail words
by value and calls `PE_func_80076C34_Inline8`. No native pointer enters guest
RAM or survives in the diagnostic record: its `arg1` field is zero and only
the eight value bytes are snapshotted. A dirty, unknown jump-table target
remains an honest indirect bootstrap boundary.

The adapter does not yet choose a guest queue address. That conversion is
only legal after the I_MASK and callback-registration dependencies permit
production to reach the retail copy loop.

## Complete retail body and dependency order

The full 172-word state machine, independently executed by the oracle, is:

1. initialize timeout through `func_800773D0`;
2. compute full as `((producer + 1) & 63) == consumer`;
3. while full, call `func_80077404`; return `-1` if it times out, otherwise
   call `func_80076EE4` and retry;
4. exchange I_MASK through `func_80073E10(0)` and save the prior mask;
5. publish marker `D_80095754 = 1` in the initialization-byte branch delay
   slot;
6. direct issue only when producer equals consumer, DMA2 CHCR bit 24 is
   clear, and DrawSyncCallback is zero; wait for GPUSTAT bit 26, invoke the
   guest worker, restore I_MASK, and return zero;
7. otherwise install the DMA2 pump identity through
   `func_80073CF4(2, 0x80076EE4)`;
8. optionally copy argument words into the current ring slot;
9. write argument, auxiliary, and worker identities;
10. publish the wrapped producer in the I_MASK-restore call delay slot;
11. call `func_80076EE4` opportunistically;
12. return `(producer - consumer) & 63`.

## Guest ring contract

The sole queue authority remains guest RAM:

```text
range       0x800BD030..0x800BE82F
entries     64
entry size  0x60
capacity    63 queued entries
producer    0x80095874
consumer    0x80095878
```

Slot `N` is `0x800BD030 + N*0x60`:

| Offset | Contents |
| --- | --- |
| `+0x00` | worker guest identity |
| `+0x04` | argument guest address |
| `+0x08` | auxiliary word |
| `+0x0C..+0x5F` | 84-byte inline payload |

Production B53C only reads producer and consumer in exact retail order. It
does not write either index or any ring byte.

The literal oracle proves the later construction order:

```text
payload words ascending
entry+0x04 = inline address (or original guest argument for copy_bytes==0)
entry+0x08 = auxiliary
entry+0x00 = worker identity
producer = (producer+1)&63       # I_MASK restore delay slot
func_80076EE4()
```

For nonzero `copy_bytes`, retail computes signed truncation toward zero of
`copy_bytes / 4` and copies that many 32-bit words. Legal recovered counts
include 8 and 64. A nonzero count whose quotient is zero copies no words but
still selects `entry+0x0C` as the argument. Retail has no inline-payload
bound check; B53C does not “improve” that behavior.

## B53B platform interaction

B53C makes exactly one hardware-authority call:

```text
func_800773D0 -> PE_GPU_VSyncQuery()
```

It does not read GPUSTAT or DMA2 CHCR yet, does not mutate readiness, does
not service DMA, does not step VBlank, and does not touch VRAM. B53B’s 15
platform tests remain unchanged and green.

No host ring, consumer, producer, worker binding, callback slot, or copied
queue payload was added. The eight-byte B52 call snapshot is diagnostic
evidence only and cannot drive queue behavior.

## Oracle

`tools/b53c_oracle.py` is independent of production C. It:

- asserts the executable SHA-1;
- embeds and verifies all 172 dispatcher words and all 13 helper words;
- checks all control transfers and exact delay slots;
- interprets MIPS-I stack, branches, MMIO reads, ring addressing, copy loop,
  publication, and returns;
- treats VSync, I_MASK, timeout, callback registration, worker, and pump as
  explicit controlled calls;
- never invents GPUSTAT evolution, DMA completion, queue consumption, or
  callback delivery.

Sixteen scenarios pass: non-full dependency, full dependency with deadline
wrap, timeout `-1`, explicit full-ring pump progress, unresolved direct
worker, controlled direct return, unresolved enqueue pump after producer
publication, empty copy-8 enqueue, nonempty copy-64 enqueue, and producer
wrap with copy zero, plus signed copy counts `-1`, `1`, `3`, `4`, `7`, and
`INT32_MIN`. The signed cases prove zero-word nonzero counts still select the
inline argument, one-word thresholds, and no invalid source dereference.
Store-order assertions prove payload before metadata and producer publication
last.
